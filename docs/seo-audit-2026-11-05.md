## Findings and deployed fixes

### High: incomplete first-request HTML

Production dynamic pages could return after a 180 ms wait before prepared data arrived. Live checks observed `/domov` with zero server-rendered detail links on one request and 36 on another. The incomplete response could then enter shared caching.

**Fix:** production Worker HTML now waits for the prepared overview and feeds. When a prepared revision is unavailable, affected pages and sitemap return a non-cacheable 503 with `Retry-After`, instead of caching an empty successful page. No visitor-side aggregation or database migration was introduced.

### High: dates generated before content was loaded

Live DOM inspection found `dateModified` set to 14 July despite visible November records. The sitemap also sometimes emitted the July fallback because its static rows were built before loading current content.

**Fix:** dynamic HTML metadata, HTTP `Last-Modified` and sitemap dates use the loaded snapshot timestamp. Static informational pages retain their actual existing dates. The published `/domov` now displays and marks up the prepared data timestamp, `2026-11-05T17:29:19.310Z`.

### Medium: broad map intent needed a clearer route to the map

`/domov`, which receives most “mapa medvedov” impressions, previously gave prominence to reporting and statistics.

**Fix:** revised the map and landing-page titles/descriptions, retained map language on `/domov`, and made “Otvoriť mapu medveďov” its primary action. Added visible map explanation and question-led guidance below the interactive map, with links to original-source methodology and safety guidance. These answers explain the distinction between reports, animal counts and live tracking.

### Medium: limited internal discovery of local pages

**Fix:** the map now links directly to the most frequent locations. `/domov` retains those links and adds an alphabetical disclosure for all remaining prepared locations. The deployed page exposes **173 distinct location links** in initial HTML. The disclosure uses native HTML and requires no JavaScript to expose its content to a crawler.

### Medium: pagination suppressed by blanket noindex and first-page canonicals

Previously `/spravy?strana=2` and `/varovania?strana=2` were noindexed and canonicalized to page one despite containing different records.

**Fix:** ordinary archive pagination is indexable, self-canonical and has page-specific metadata. Filtered searches and alternate page sizes remain noindexed. The HTTP canonical header, HTML canonical and structured-data URL agree. This follows [Google's pagination guidance](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading).

### Low: generic keywords presented as alternate brand names

**Fix:** `WebSite.alternateName` now contains the actual brand spelling and domain fallback, rather than broad category terms. Dataset license links now use the canonical terms URL. This follows [Google's site-name guidance](https://developers.google.com/search/docs/appearance/site-names).

Existing server-rendered JSON-LD, FAQ content on `/domov`, source attribution, RSS and `/llms.txt` were retained. `robots.txt` already allows public content to search crawlers. No unsupported promise about special AI files or schema causing higher rankings was used; Google's [AI-features guidance](https://developers.google.com/search/docs/appearance/ai-features) emphasizes ordinary indexing and helpful content.
